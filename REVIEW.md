## Высокий приоритет

1. **Двойная навигация и риск неверного результата при исчерпании слов.** `PlayViewModel.kt:127` устанавливает `wordsExhausted` до обновления счёта в `endGame()`. Наблюдатель `PlayActivity.kt:132` сразу открывает индивидуальные результаты со старым списком игроков; затем наблюдатель `gameEnded` на строке 120 открывает командные результаты. Оставить один сигнал завершения, обновлять игроков перед его отправкой, отменять таймер и сделать завершение идемпотентным. В ветке исчерпания слов таймер сейчас не отменяется.

2. **Загрузка нескольких наборов меняет текущую карточку и может преждевременно закончить игру.** `PlayViewModel.kt:159–180`: каждый независимый ответ Firebase вызывает `prepareRoundWords()`. Пустой первый набор сообщает об исчерпании до ответа остальных; непустые ответы заново перемешивают раунд и заменяют показанное слово. Таймер запускается до загрузки (`:107`). Сначала дождаться всех ответов, обработать ошибки, затем один раз подготовить слова и запустить таймер. Отбрасывать ответы после выхода или завершения раунда.

3. **Слова, добавленные в игре, нельзя надёжно удалить или отредактировать.** `PlayViewModel.kt:275` использует `.add()` с автоматически созданным ID, а `My_set_activity.kt:224,327,364` обращается к `.document(word)`. Удаляется другой документ, оригинал остаётся; редактирование создаёт дубликат. Сохранять реальный ID документа вместе со словом и использовать его для всех операций. При переименовании старый документ удаляется до подтверждения сохранения нового (`My_set_activity.kt:327`), что также создаёт риск потери данных; нужна атомарная операция.

4. **«Мой набор» общий для всех установок.** `PlayViewModel.kt:258–262` и `My_set_activity.kt:183–187` используют общий путь `languages/{language}/categories/MySet/words`; UID пользователя в пути нет, а вызовов аутентификации в исходниках не найдено. При разрешённой записи пользователи меняют один общий набор; при запрещённой записи функция не работает. Для личных наборов нужны аутентификация, путь с UID и соответствующие правила Firestore. Наличие открытых правил в действующей базе не подтверждено.

## Другие существенные проблемы

5. **Поворот экрана сбрасывает раунд.** `PlayActivity.kt:42` при каждом `onCreate` вызывает `startGame()`, который заново инициализирует сохранённый ViewModel и очищает раунд. Запускать новую игру только при отсутствии уже инициализированного состояния; для восстановления после завершения процесса использовать сохранённое состояние.

6. **Некорректный индекс игрока вызывает падение.** `PlayViewModel.kt:220` обращается к списку без проверки индекса из Intent. Внутренние Activity, включая PlayActivity, экспортированы в манифесте. Проверять список и индекс при запуске; для экранов без внешних сценариев выставить `exported=false`.

7. **Неуспешная начальная загрузка больше не повторяется.** `MainActivity.kt:66–71` записывает `is_first_run=false` и сообщает об успехе, не дожидаясь асинхронного `batch.commit()` из WordsViewModel. При ошибке сети/правил база остаётся незаполненной. Устанавливать флаг только после успеха всех нужных операций, показывать ошибку и разрешать повтор.

8. **Тесты не подтверждают игровую логику.** `PlayViewModelTest.kt` проверяет отдельную `PlayViewModelForTest`, не production-класс. Нужны проверки реального ViewModel с подменой источника слов и таймера: несколько наборов, пустой набор, запоздалый ответ, завершение ровно один раз, счёт последнего слова, восстановление экрана.

## Подготовка к публикации

В исходной Git-истории отслеживаются google-services.json, APK и настройки IDE. Простое добавление .gitignore не удаляет их из истории. Поэтому подготовлена отдельная копия без старой истории и этих файлов; оригинал сохранён. Конфигурация Firebase сама по себе не доказывает утечку административного секрета, но для публикации здесь исключена привязка к исходной базе. Поиск типичных маркеров приватных ключей, GitHub-токенов и встроенных паролей в просмотренном рабочем дереве совпадений не дал; полной проверки секретов во всей истории не проводилось.

Логика приложения в подготовленной копии совпадает с исходником. Исправления из этого отчёта ещё не внесены.
